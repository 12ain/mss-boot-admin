## 本次范围

- 工作台支持受权限约束的业务内容注册；头像面板、页头和页脚支持编译期扩展，
  保留官方账号操作与布局控制。
- 修复登录、注册和密码找回成功后的导航延迟；隔离业务扩展渲染失败，正确处理
  头像面板内浮层交互及退出后的状态清理。
- 修复普通 CRUD 生成模块在可选事件、校验、搜索和唯一约束组合下的测试生成。
- 限制前端压缩任务并行度和 Tailwind 扫描范围，降低外部应用构建内存占用。
- 修复文档依赖审计对同一漏洞不同依赖记录的处理，更新已有补丁的构建依赖。
- 修复外部 Thin Host 检查自行改变 Foundation 工作区校验和的问题。

## 发布流程

1. 修复和版本准备通过 PR 合入 `main`，同一提交的 main 检查全部成功。
2. 在该提交依次创建 Framework、Admin、Frontend 和 Root 标签。
   标签流水线自行构建；前端构建结果供前端发布、Root 归档和 npm 共用。
3. Root 标签自动启动 npm 发布。只读检查等待同一提交的 main 和上述标签流水线
   （包括 Root 镜像）全部成功，再通过 OIDC 发布已经生成的 npm 压缩包。
4. npm 包的版本、提交、完整性、来源证明和 `latest` 核实后，更新 Root GitHub Latest。
   最后同步仓库的当前稳定版本事实。

无需独立预演、额外本地全量发布验证或专门的稳定晋级授权 PR。
源码审查、main 检查、版本不可覆盖、同提交身份和 npm 来源证明继续保留。
完整检查可用于诊断故障，不作为流水线已经通过后的重复发布门槛。
具体工作流职责见[工作流维护](../coding/workflow-maintenance.md)。

失败时优先重跑同一运行中失败的 job，复用成功构建的产物。npm 重跑仍须核实
main 和标签检查；已有且一致的包只做核对，出现不同提交或字节时拒绝覆盖。
已公开的组件标签和镜像不移动、不重建覆盖，也不回退 `latest`。

## 兼容、迁移与回退

本次发布不增加业务数据库迁移或权限。业务扩展是编译期可选功能，升级时保留
业务自有注册文件；运行时动态模型和浏览器代码生成仍不可用。
工具、Framework、Admin、前端包及镜像统一为 v1.3.8；采用时固定同一协调版本，
不要混用 v1.3.7 组件、配置或锁文件。

回退需要恢复匹配版本的组件、配置、锁文件和数据库备份，不混用补丁版本。
文档站部署独立进行；Docs 在 main 的构建检查不等于已经更新公共网站。

### 安装与升级

安装、初次创建和公共包验证从[快速开始](/getting-started)、
[工具说明](/getting-started/tooling)和[包与导入边界](/getting-started/packages)进入。
已有 Thin Host 先备份代码、配置、锁文件与数据库，安装匹配的 v1.3.8 工具，
确认 `.mss/blueprint-manifest.json` 存在，再执行：

```shell
mss --version
mss-mcp --version
mss upgrade admin v1.3.8 --format json
mss upgrade admin v1.3.8 --apply --yes --format json
mss doctor --strict
mss verify --all
mss upgrade admin v1.3.8 --format json
```

首尾计划均为只读，最终必须没有变更或冲突。升级只修改 Blueprint 受管文件，
保留业务自有和未知文件。手工拼装或丢失 manifest 的应用，应在新目录生成干净的
v1.3.8 基线后迁入业务文件，不能伪造升级来源。
